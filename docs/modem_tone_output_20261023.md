# Original modem tone generation and physical output, 23 October 2026

Follow-up: the overlay's other generators — the V.8bis 1080/1750 Hz
carriers and the complete V.21 FSK generator — are now measured on the
same eight DSPs in [modulation tone generators](modulation_tone_generators_20261023.md).

**Verified on all eight DSPs of spare SN12196:** the original V8.ANA ANSam
routine generates a 2100 Hz carrier, and samples derived from that hardware
output transmit and return exactly through the physical SPORT1/IPAC loop.
No active BRI line is required. Stock firmware was restored after both runs;
primary SN1331 and its answerer/SIP services remained active.

## Generator comparison

`tools/eicon_modem_tone_replay.py` imports the original V8.ANA build-109
routine at PM `3a02..3a28`, its oscillator/interpolator at `3f2f..3f41`,
and the unmodified 128-word lookup table at `3c80..3cff`. They remain at their
original addresses. The driver initializes M4=0, M5=M6=1, zero carrier and
modulator phase, phase-reversal countdown 4321, and gain `DM(0769)=4000`.
It calls the original generator and stores MR1 after every call, with SPORT
and interrupts disabled. The BRI interfaces remain in reset.

Each chip generated **7,680 samples**, giving **61,440 physical samples**.
Every output and all five final state words match the emulator exactly.
At the routine's native 9600 samples/s, a windowed frequency scan peaks at
2100 Hz. The phase increment `0033` gives 14.9414 Hz amplitude modulation;
the carrier phase reverses near 450 ms, also verified from the captured
waveform. This first stage is offline generation; the WAV rate specifies
the intended sample cadence rather than measuring how fast the batch ran.

[Native hardware-generated recording, 0.8 seconds](../artifacts/dsp-conformance-20261023/tone/hardware-ansam-9600.wav)

## Physical SPORT output

The working IPAC SPORT1 connection runs at nominally 8000 words/s. Playing
9600 Hz samples unchanged would alter pitch, so the host uses the existing
64-tap `RationalResampler(5,6)` on the **actual hardware-generated samples**.
It selects converted samples 400..1039, after filter startup, as a
640-word playback cycle. The resampling and selected words are preserved
and regenerated by a test; this is not a host-created substitute sine wave.

The spare-only stock-interface takeover preserves IPAC clocks and selects
the existing CDA DD-to-DU loop, with no static DD driver. The DSP transmits
the cycle using SPORT1 TX autobuffering and receives into a separate
1024-word ring. Control `3c0f` selects external clocks/frames and alternate
sixteen-bit framing. No DSP clock/frame output is enabled.

A bounded foreground wait runs 8191 × 2048 NOPs. TX/RX wrap interrupts count
through separate DAG registers without modifying arithmetic state. The
program then disables SPORT1 and copies the whole RX ring starting at its
next-write pointer, producing chronological samples. Every chip recorded
three TX wraps and two RX wraps, proving the RX ring had filled completely.

All **8,192 returned samples** match the transmitted 640-word cycle exactly,
allowing only the independently observed starting phase. Five chips start
at cycle offset 382, three at 383. All eight returned streams peak at
2100 Hz when analyzed at the nominal 8000-word/s cadence.

[Physical SPORT1 receive-back recording, 0.128 seconds](../artifacts/dsp-conformance-20261023/tone/hardware-sport1-received-8000.wav)

This verifies digital serial output through the actual card wiring/IPAC,
not analog audio at a telephone connector. Playback repeats a short segment,
so it does not preserve the complete ANSam modulation/phase-reversal timing.
The generator and output tests are two stages; this is not yet an original
modem task generating samples continuously in a live SPORT ISR.

## Reproduction and evidence

```sh
python3 tools/eicon_modem_tone_replay.py \
  --out generator.json --bundle generator.bundle
python3 tools/dsp_conformance.py emulate generator.json --out generator.emu.json
# Run generator.bundle with the stopped-spare procedure, retrieve generator.card.json.
python3 tools/eicon_modem_tone_replay.py --wire-from-card generator.card.json \
  --out wire.json --bundle wire.bundle
```

The optional bundle builder selects the recorded reset masks and quiet
windows automatically: generator uses DSP-only release and one million
boot-settle iterations; playback preserves IPACs with hold `1e` / release
`1f` and five million iterations. Use the standard runner with exact spare
identity `--pci 0000:02:02.0 --adapter 5 --serial 12196`. The wire stage
requires `--takeover-stock-interfaces --ipac-fixture loop`. Always restore
stock firmware with the corresponding EXIT handler, as documented in
[sample replay](dsp_sample_replay_20261023.md) and
[SPORT patterns](sport0_tx_patterns_20261023.md).

`tests/data/modem_tone_card12196.json` contains original firmware words,
boot payload hashes, actual generator output, conversion provenance,
transmitted words and physical receive-back results. Raw specs, bundles,
captures and recordings are under `artifacts/dsp-conformance-20261023/tone/`.
Six tests cover every generated word, carrier and phase reversal, conversion
provenance, every received word, corrupted-word rejection, bounded no-clock
completion, and the wire program with emulator word events.

```sh
python3 -m unittest discover -s tests -p test_eicon_modem_tone_replay.py -v
```
