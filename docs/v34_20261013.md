# V.34 mailbox fixes and rate-bounded PPP — 13 October 2026

**Update, 14 October:** the remaining high-rate defect was ADSP emulator
add-with-carry overflow. The corrected core passes 21600 and 26400 PPP
controls without disabling quality fallback. See [the correction and
evidence](v34_adc_20261014.md). The results below are the historical mailbox
and rate-bounded baseline.

The mixed Analog build-109 / PRI build-117 pair carries real V.34 PPP at
9600 bit/s in both directions. Unrestricted 26,400/28,800 negotiation still
retrains; this is not a claim that all V.34 rates now work.

## Concrete mailbox faults

The current baseline, `artifacts/v34-20261013-current`, reaches DATA but
never establishes PPP. Its first caller retrain marker is sample 167892
(20.986500 s), wall time 1791864913.368119; answerer DATA exit is sample
154031 (19.253875 s), wall time 1791864913.582276. Comparing local sample
clocks would reverse the initiator. A bounded execution watch resolves the
caller marker to PM `0x2D63`, called from `0x2490`. A delayed write watch then
shows the script decoder at `0x2E21` writing DM(0x2139)=8, which invokes
that handler through the event table. This is not the `0x25D5` quality-timer
branch initially suspected; that address also contains other code during
partial-overlay execution. The marker handler writes DM(0x2252)=7.

`artifacts/v34-20261013-schedule` samples the actual transmit scheduler for
1000 consecutive bearer samples. PM `0x3FB3..0x3FC2` clears and reasserts
DI_control bit F within a single DSP pass. DM(0x14AE) steps through 2, 1,
and 0 while F stays set; the old host waited for a visible falling edge,
repeating TXD0 within each period. The capture contains 300 scheduler steps
on the PRI end and 301 on the Analog end over 125 ms, consistent with
2400 datagrams/s (the one-event difference is the bounded-window edge).
`V34Mailbox` now services each scheduler step, as it already did for V90A.
The TX-only A/B recognizes the answerer's ADP, but still cannot complete
LAPM or prevent retrain: this fixes a real host fault, not the whole signal
failure.

The Analog kernel runs at 9600 codec frames/s, while the media loop runs at
8000 bearer samples/s. `AnalogKernelModem` now owns mailbox callbacks around
each actual codec frame; SIP avoids also polling it at bearer boundaries.
A firmware-backed test checks the before/frame/after ordering over 120 codec
frames generated by 100 bearer samples, including samples that generate two
codec frames. The first retrain initiator changes to the answerer in the
codec-frame A/B, but high-rate LAPM still fails.

V.34 detection activation also now waits for DATA plus CTS/RFS and DCD/RSD,
as V.42 7.2.1 requires. This avoids clocking detection on the provisional
`0x00C6` publication before the receive direction is ready. It is not a cure
for the high-rate signal-quality decision: later samples show both
DM(0x2147) and DM(0x2152) at `0x00D0`, with DM(0x2202)=2 selecting fallback.

The originator's detection diagnostic counted only ODP scans and incorrectly
reported "no bits reached the detector" while it was scanning ADP. Both
roles now count their incoming detection bits and name the proper pattern.
The historical V.42 startup logs still contain that misleading message;
ODP/ADP success in the corrected clock A/B remains valid, but that message
cannot establish absence of originator RX bits.

## Working 9600-bit/s control and normal configuration

`artifacts/v34-20261013-9600-control` selects the documented capability bit
for 9600 in ADDSP write DB `speed_sel_l` (DM 0x3F0B bit 10), with the high
mask zero, on both endpoints. These are negotiation limits, not modem-state
pins. The guide and `docs/addsp_database.md` give the bitmap; the capability
mask is distinct from the negotiated DATASTATE words.

That 60-second run negotiates `speedTx=0x000A`, `speed=0x110A`: four bits
per 2400-Hz datagram, or 9600 bit/s in both directions. LAPM connects,
CHAP authenticates, IPCP opens, and **25/25 pings** get replies. Caller DATA
is continuous for 40.12 seconds and answerer DATA for 39.92 seconds. Neither
logs a retrain; both PPP summaries have zero FCS errors and link resets.

The direct configuration previously honored only the modulation menu and
silently ignored rate bounds. Strict V.34 now builds the ADDSP common speed
bitmap from the intersection of the requested TX/RX ranges. A disjoint pair
is rejected because this direct interface cannot express separate masks.
Unbounded selections preserve their previous defaults. Other modulation and
automode rate-bound handling is not changed by this patch.

Use normal rate options rather than raw database overrides:

```sh
/Users/scottcryan/v90modem/.venv/bin/python tools/eicon_loopback.py \
  --python /Users/scottcryan/v90modem/.venv/bin/python --seconds 100 \
  --caller-firmware-set analog109 --answerer-firmware-set pri117 \
  --caller-modulation v34,0,9600,9600,9600,9600 \
  --answerer-modulation v34,0,9600,9600,9600,9600 \
  --caller-kernel-dispatch --ppp --ppp-ping peer --ppp-ping-count 65 \
  --trace-retrain --capture-dir artifacts/v34-20261013-9600-fixed
```

No PLL patch, detection-disabling option, quality-control override or forced
training state is needed for this V.34 configuration.

The 100-second normal-option repeat passed: caller DATA spans samples
136160–776640 (80.06 seconds), answerer DATA spans 122240–761120 (79.86
seconds). All 65/65 pings get replies, with no retrain, PPP FCS errors or
link resets. Shutdown is the only reason IPCP/LCP go down.

Two higher bounded-rate runs also establish real PPP with zero FCS errors,
zero link resets and no retrain:

| Capture | Rate in both directions | Ping replies |
|---|---:|---:|
| `v34-20261013-14400` (60 s) | 14,400 bit/s | 30/30 |
| `v34-20261013-19200` (50 s) | 19,200 bit/s | 20/20 |

For the tested 19,200-bit/s configuration replace each modulation argument
with `v34,0,19200,19200,19200,19200`. The longer endurance result is the
9600-bit/s run. Extracted endpoint summaries are retained in
`artifacts/v34-20261013-evidence.json`.

Validation: 77 LAPM tests, 15 mailbox tests, 15 firmware-backed Analog kernel
tests, five direct modulation tests, 32 V.90 tests and 11 SIP hangup tests
passed. Python compilation and `git diff --check` also passed.

## Controls and limitations

- `artifacts/v90-20261013-mailbox-control` retains the existing PCMU law and
  V90D TX representation fixes: default V.42 detection, CHAP/IPCP and 35/35
  pings pass after the codec-frame mailbox change. No DATA exit is observed.
- The physical Analog SPORT TX latch comparison also retrains. Its callback
  already masks output to unsigned 16-bit words; a suspected signedness
  issue was ruled out and the unnecessary edit removed.
- `artifacts/v34-20261013-schedule-fixed` ran an unintended width-selection
  edit and is excluded from the A/B evidence. The corrected run is
  `v34-20261013-tx-fixed`.
- The old V90D result's upstream rate description is corrected: 13 bits at
  2400 Hz is 31,200 bit/s, not 17,333. The downstream mapping clock is
  8000/6 Hz; the two directions do not share a datagram frequency.

The higher-rate receive-error source remains unresolved. Do not disable
quality fallback or pin DM(0x2202) to make a link appear stable. Rate-bounded
PPP is a local Analog/PRI result, not a hardware interoperability result.
