# PCM path audit, 13 October 2026

The transport is clean in the measured windows, but the default analogue host resampler is not transparent near the top of the modem band. This is a measured host-path defect candidate; it does not yet establish the cause of the remaining high-rate V.34 retrain.

## Wire and amplitude checks

Compared each endpoint's transmitted `.ulaw` with its peer's received `.rx.ulaw`, starting at sample 160000 (20 seconds), through the common end of the captures:

| Capture | Caller to answerer | Answerer to caller |
| --- | --- | --- |
| `v34-20261013-ready-fixed` (failing unrestricted V.34) | 257120 bytes, zero differences | 257600 bytes, zero differences |
| `v34-20261013-19200` (passing V.34) | 217280 bytes, zero differences | 217600 bytes, zero differences |

Both have zero alignment offset in these files. None of these windows contains the maximum-magnitude PCMU codes 0x00/0x80. Decoded waveform peaks are 7164–7676 PCM16 units, well below full scale. These checks exclude captured wire corruption and G.711 rail clipping, not every internal DSP arithmetic or sample-presentation fault.

## Resampler measurement

Executed the current `RationalResampler` class extracted directly from the source AST, without loading or patching firmware. Fed one second of a 10000-unit sinusoid, discarded 100 output samples at each end, fitted sine, cosine and DC, and measured the remaining residual. The fitted gain absorbs constant gain and phase; residual SNR measures the non-sinusoidal output, including interpolation images. This is a tone measurement, not a modem BER or complete channel SNR.

| Converter | Frequency | Default 16 taps: gain / residual SNR | 64 taps: gain / residual SNR |
| --- | --- | --- | --- |
| 8 to 9.6 kHz | 3000 Hz | +0.0125 dB / 52.41 dB | -0.0091 dB / 61.36 dB |
| 8 to 9.6 kHz | 3400 Hz | -0.3512 dB / 27.53 dB | +0.0096 dB / 60.22 dB |
| 8 to 9.6 kHz | 3600 Hz | -1.2307 dB / 16.30 dB | +0.0074 dB / 61.71 dB |
| 9.6 to 8 kHz | 3400 Hz | -0.7069 dB / 55.50 dB | -0.0105 dB / 66.79 dB |

At 1000–2400 Hz the default input converter's measured residual SNR is 59.94–69.53 dB. The deterioration is frequency dependent, not a uniform scaling error. Increasing taps substantially improves this synthetic measurement; it also changes filter delay and costs more CPU, so a live control is necessary before changing defaults.

Reproduction script and machine-readable measurements are in `artifacts/pcm-path-audit-20261013.py`, `artifacts/pcm-path-audit-20261013.json`, and `artifacts/pcm-path-audit-20261013-64.json`. Run the script from the repository root with the project Python and NumPy installed. The 64-tap variant changes only the resampler constructor's `taps_per_phase`.

The caller's linear input masks to 16 bits before sign extension; its SPORT callback already normalizes output to an unsigned 16-bit word. The existing V.90D PCMU expansion and encoder-table law fixes remain intact. No gain override or quality-fallback suppression is part of this audit.

## Live longer-filter control

`artifacts/v34-20261013-pcm64` ran 55 seconds with strict unrestricted V.34 on both endpoints and `--caller-env EICON_ANALOG_RESAMPLER_TAPS=64`. The log confirms sinc/sinc 64/64 taps, no gain override. Caller DATA exits at samples 170947 (21.368375 s) and 301990 (37.748750 s); V.42 reports T400 expiry with no ADP match. PPP never establishes. Caller media counters through 50 seconds report zero substituted samples, zero dropped samples, zero TX underruns, and zero clock holds. The longer filter does not cure the high-rate failure, despite its much cleaner synthetic band-edge response. Defaults were therefore left unchanged pending a targeted internal sample/symbol comparison.

## Corrected default PCM conversion

The subsequent change uses a 64-tap Blackman window and normalizes each polyphase branch to unity DC gain. It also fixes startup indexing: zero history now occupies negative input indices, and the FIR runs causally instead of counting that padding as received samples. The old default emitted 9612 output samples for 8000 inputs and 8009 for 9600 in the opposite direction; the corrected converter emits exactly 9600 and 8000 respectively. More importantly, its cumulative output count is `ceil(N * up / down)` from the first input, with no initial codec-frame burst. Filter group delay is 4 ms into the codec and 3.33 ms out, fixed rather than drift or skipped samples.

The corrected converter's measured input-direction residual SNR is 81.07 dB at 3400 Hz and 78.99 dB at 3600 Hz, with gain -0.0008 and -0.0010 dB. The output direction measures 112.38 and 108.00 dB at those frequencies, with gain +0.0015 and -0.0030 dB. These floating-point conversion measurements precede intentional PCM16 rounding and G.711 companding. They do not imply lossless transport through G.711.

Three regression tests in `tests/test_pcm_resampler.py` verify cumulative cadence at every input (including startup), bounded history, phase-independent DC gain, and tone gain/residual SNR in both directions at 1000, 3000, 3400 and 3600 Hz. The gain tolerance is 0.01 dB and the residual SNR floor is 70 dB. Machine-readable results are in `artifacts/pcm-path-audit-20261013-clean.json`.

For historical reproduction after this change, the original class is saved as `artifacts/pcm-resampler-before-20261013.py`. The audit script accepts a source file and output JSON path as its two optional arguments; without arguments it measures the current source and writes a separate `-rerun.json`, preserving the recorded baseline.

The corrected-default unrestricted V.34 capture `v34-20261013-pcm-clean` still exits DATA after approximately 4.4–4.8 seconds. Answerer exit wall time 1791868217.514539 precedes caller exit wall time 1791868217.746300. This fault remains open; no quality thresholds were changed.

The 60-second 19.2 kbps control `v34-20261013-pcm-clean-19200` answers 30/30 PPP pings and holds both ends continuously in DATA for 40.10 / 39.90 seconds, with zero FCS errors, link resets or retrain exits. This confirms the new default retains the working data path. The 3 new PCM regression tests, 15 firmware-backed analogue tests and 5 V.90D TX/law tests pass.

A separate steady-state polyphase response sweep at 50 Hz increments from 50 to 3600 Hz bounds input gain error at 0.00149 dB and residual SNR at 75.32 dB (both worst at 3500 Hz). Output gain error is at most 0.00300 dB; output residual SNR is at least 103.53 dB. This calculates the coherent response and the variance across all fractional phases directly from the actual coefficients, independently of streaming startup. Results: `artifacts/pcm-filter-grid-20261013.json`.

The documented V.90A caller / V.90 answerer control `v90-20261013-pcm-clean-control` ran 80 seconds with the existing caller PLL diagnostic and PCMU channel-law/TX expansion fixes. It answers 45/45 PPP pings, holds DATA continuously for 54.86 / 54.56 seconds and reports zero FCS errors, link resets or retrain exits. TX-to-peer-RX comparisons from sample 200000 match 417280 / 417760 bytes exactly, with zero offset and zero differences. Summary: `artifacts/pcm-clean-live-evidence-20261013.json`.

An earlier `v90-20261013-pcm-clean` attempt incorrectly selected strict `v90,0` for the analogue caller instead of `v90a`; it never trained and is excluded from regression evidence.
