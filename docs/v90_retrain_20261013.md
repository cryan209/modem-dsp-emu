# V.90 loopback retrain investigation — 13 October 2026

## Reproduction

The default loopback caller is PRI, so specify both firmware families and
modulations. A PRI/PRI run is not the Analog/PRI control.

```sh
python tools/eicon_loopback.py --python /path/to/python-with-unicorn \
  --seconds 75 --caller-firmware-set analog109 --answerer-firmware-set pri117 \
  --caller-modulation v90a --answerer-modulation v90 --caller-kernel-dispatch \
  --caller-env EICON_PATCH_PM=0x0e3a:0x0a000f:0x026b \
  --caller-env EICON_V42_DETECT=0 --answerer-env EICON_V42_DETECT=0 \
  --ppp --ppp-ping peer --trace-retrain \
  --capture-dir artifacts/retrain-20261013-analog
```

The interpreter used here was `/Users/scottcryan/v90modem/.venv/bin/python`
(Unicorn 2.1.4). No external SIP account or hardware was used.

## Initiator correction: compare wall time, not local DSP time

The endpoints have different sample-clock origins. The old description of an
answerer-initiated retrain compared local seconds directly and is incorrect
for these reproductions. In the baseline the caller's event wall time is
`1791861049.491715`, and the answerer's is `1791861049.647169`: **the caller
leaves DATA first, by 155 ms**. The bounded edge run repeats the ordering:
caller `1791861544.997892`, answerer `1791861545.155316` (157 ms).

The 200-sample window in `artifacts/retrain-20261013-edge60` establishes
V90D test 3's event: DM(0x0E11) rises to 30 at sample 387008;
the resolved handler is PM `0x30AE`, the cursor changes from `0x1C44` to
`0x1D01` at sample 387009, and published TrnProgress becomes `0x00BD`
at 387010. The rate estimate remains zero. Before that threshold,
DM(0x11F5) is near +4700 while DM(0x11F6) alternates near ±4700,
producing the repeated sign pattern. This is the answerer's response to an
incoming signal pattern, not evidence of a 28-second answerer timer.
The caller state trace (`artifacts/retrain-20261013-caller`) additionally shows
its rate-change script starts at local sample 400925 (50.115625 s), while
TrnProgress still reports DATA. The record pointer changes to `0x1983`, then
`0x198C` at 401245, then the `0x00C1` record at 401285. Thus the signal
change starts before the published DATA exit; state publication alone cannot
establish who initiated it.

The DATA pretest is PM `0x34AE`: it checks the host rate-change edge and
DM(0x1DCB), then resets local rate-control bookkeeping. PM `0x0C32..0x0C5B`
can set DM(0x1DCB) from a 16-observation average of DM(0x0EF7) when
GEN_setup2 enables quality fallback or step-up. The setup value `0x0070`
enables both. The guide defines those as signal-quality-driven rate controls;
no diagnostic change to those controls has been made.
The next measurement was the actual DM(0x1DCB) writer and its threshold inputs.

## Caller trigger: quality fallback, not step-up

`artifacts/retrain-20261013-quality-fixed` successfully arms the delayed
watch on the Analog backend with the colon-format PLL patch still active.
The watch names PM `0x0C58` writing DM(0x1DCC)=1, followed by PM `0x0C59`
writing DM(0x1DCB)=1 and `0x0C5A` writing DM(0x1DCD)=1. Its preceding-PC
history includes `0x0C42..0x0C4C`, the 16-observation quality average and
fallback comparison. At that comparison SR0 is `0x023A` (570), and AR
is `0xFF06` (-250): the fallback threshold is 320 and 320 - 570 = -250.
The subsequent samples show DM(0x0EF7)=572, DM(0x1FA4)=320 and both
request flags set. Thus it is the **quality fallback branch**, not the
step-up branch at `0x0C56`, that initiates the rate-change script.

This instrumented run had some clock holds, so its shifted event sample
401120 is not a replacement deterministic oracle. It confirms the branch
and operands, and confirms the delayed watch no longer drops the call.
The baseline, bounded-history and answerer edge captures establish the
repeatable timing and endpoint ordering independently.

The next causal target is the caller receive-error metric DM(0x0EF7): trace
its writer and convergence across DATA, against actual downstream bit errors
and a hardware reference. Do not disable quality fallback or pin its request
flag as a connection fix. The firmware is making a measured quality decision;
the receive-error source still needs correction.

## Exit tests and instrument correction

V90D resolves tests through **DM(0x05E0)**, and branches through
**DM(0x0613)**, as loaded at PM `0x2FC5..0x2FC9` and `0x2FC0..0x2FC4`.
The V34/V90A test table at `0x064B` is not the V90D table.
In DATA the live resolved test handlers are:

| test | handler | observed implementation |
|---|---|---|
| 0 | `0x3075` | rising-edge test of GEN_setup2 bit 0, using DM(0x208B) |
| 1 | `0x3015` | `1200 - DM(0x2117)` |
| 2 | `0x306C` | GEN_setup6 bit 9; otherwise DM(0x0A9A) bit 15 |
| 3 | `0x30AE` | `30 - DM(0x0E11)` |

Before the exit the sampled rate estimate is zero, GEN_setup2 is `0x0070`,
GEN_setup6 `0x2105`, and DM(0x0A9A) is zero. DM(0x0E11) is normally 0–3
in the final second's 20 ms samples. These snapshots alone do not prove which
condition fires inside the event sample.

A bounded positive write watch confirms DM(0x0E11)'s writer at PM `0x327E`.
PM `0x3269..0x3283` counts repeated sign-pattern differences derived from
DM(0x11F5/0x11F6) through the small history at DM(0x211C).
Naming that signal as a retrain tone requires further evidence.

The standalone disassembler wrapper previously passed a pointer to the current
word while the decoder indexed it again by absolute PC, with byte rather than
word addressing. This could print a mnemonic unrelated to the displayed opcode
and read outside the PM array. The wrapper now uses the whole PM buffer with
word addressing, validates the requested range, and has a nonzero/high-address
regression test. Rebuild with the single `dasm_main.cpp` source; it already
includes the implementation.

`--trace-retrain` now preserves the resolved V90D handlers, branch targets,
record/dwell, and their inputs in its existing bounded history. No modem state
is forced by this change.

## Delayed-watch harness fault (fixed)

The first attempt to arm the caller's bounded watch at 50 s failed in the
instrument, before the natural retrain. `_arm_dm_assertion()` imported
`eicon_mips_shim`, which parsed the direct backend's colon-separated
`EICON_PATCH_PM` as MIPS's `ADDR=WORD@OVERLAY` syntax and raised `ValueError`.
That dropped an otherwise connected call. The method now uses the DSP API
already imported by the endpoint, as `_arm_watches()` does. A regression test
forbids importing the MIPS backend while arming a direct-backend watch.
`artifacts/retrain-20261013-quality` is an instrument-fault run and must not
be used as a natural-retrain result.

## Receive-error measurements and controlled comparisons

`artifacts/retrain-20261013-error` samples the caller once a second. The
error is 260 at 23 s, 559 at 24 s, then stays about 552–585 through DATA.
It does not gradually grow toward the threshold: the 16-observation quality
monitor accounts for the delayed fallback request.

The metric writer is PM `0x2D90`. PM `0x2E39..0x2E4C` accumulates squared
decision residuals in DM(0x21D2/0x21D3), counted by DM(0x21CF). The metric
routine divides by the count, takes an integer square root, then scales by
52/8. Isolated execution of the actual firmware routine with known inputs
gave the expected results: RMS 20 -> 130, RMS 49 -> 318, RMS 89 -> 578,
and RMS 100 -> 650 at count 4000. RMS 89 also gives 578 at count 3078.
This checks those arithmetic cases, not every DSP instruction or input.

The captured 29-bit downstream mailbox words have a unique zero-error
alignment at offset 44 over words 200–1500. Four subsequent windows, ending
at receive word 35000 before retrain, have bit-error rates of about 0.015%,
0.018%, 0%, and 0.038%. These are selected aligned DATA windows, not a
whole-call BER or proof of a continuously healthy PPP link.

Two single-variable comparisons retained the same high error and retrained:

- `artifacts/retrain-20261013-phase3`: input resampler phase 3 instead of 0.
- `artifacts/retrain-20261013-taps64`: 64 taps per phase instead of 16.
  At 23–34 s its sampled metrics match the original error run; the caller
  publishes its DATA exit at sample 403178 (50.397250 s).

Neither change is adopted as a fix. Next measure observed symbol magnitudes,
chosen constellation levels, and residuals at DM(0x24EF/0x24F2/0x24F1).
PM `0x2E12/0x2E13` writes the latter pair. This will distinguish systematic
amplitude error from other distortion before changing equalizer behavior.
The planned passive symbol capture was not executed: automatic approval
review failed to refresh the signed-in account token. Resolve account sign-in
before resuming local UDP loopback runs.

## Targeted TX boundary fix and successful PPP validation

The unresolved status above describes the investigation before the following
closed-loop comparisons. No V90D timer or DATA-exit test was patched.

`artifacts/retrain-20261013-symbols` sampled DM(0x24EF/0x24F2/0x24F1)
every eight bearer samples for four seconds starting at 24 s. The selected
level had a repeatable amplitude-dependent residual: mean observed-minus-
decided magnitude was -79.0 at level 2364, +154.2 at 4604, and -229.8 at
8316 (285, 246, and 242 observations respectively). The quality metric was
559–578. The run again left DATA after about 27.5 seconds. These are bounded
snapshots, not a whole-stream error distribution.

`artifacts/retrain-20261013-map` then captured the caller's 128-word
DM(0x1F24..0x1FA3) level table and 4000 consecutive answerer output words.
The caller table is in PCM16 units and ends at 32124. The answerer published
levels such as 1151, 2079 and 295 rather than their PCM16 values 4604, 8316
and 1180. The serializer instruction establishes the conversion explicitly:

```
2eed  I0 = DM(0x20DE)
2eee  AR = DM(I0,M1)
2eef  DM(0x20DE) = I0
2ef0  SR = ASHIFT AR (LO) BY -2
2ef1  DM(0x3FA7) = SR0
```

TIKRNL PM `0x1A1E` publishes that serializer port to DM(0x3FB4), which
`Card.frame_fast()` returns to `_queue_rtp()`. The independent codec's
`encode_g711()` accepts PCM16. Passing the SPORT-scale value instead makes
G.711 quantize the negotiated symbol a second time at a different scale.
The caller's equalizer can compensate overall gain but cannot remove this
level-dependent distortion.

The single-variable A/B `artifacts/retrain-20261013-tx4` used the existing
`EICON_V90D_TX_GAIN=4` diagnostic with the PCMU channel-law fix retained.
It held DATA for about 49.6 seconds on the answerer and 49.9 seconds on the
caller, answered 45/45 PPP pings, and reduced the caller metric to 45–52.
The older native-MIPS scale A/B was a different backend and predates the
current direct channel-law fix; its policy has not been changed.

The production change is `Card._v90d_tx_pcm16()` in
`tools/dial_tikrnl_drive.py`, called after reading the serializer output and
before optional diagnostic gains. It expands only direct `pri117`, resident
V90D, PCMU output to PCM16. It preserves the +/-2 signed-zero tokens and
leaves words larger than the 14-bit range unchanged (including the generic
context-restore pointer). It changes neither mapping-frame lifetime nor
receive scaling. `configure_g711_law()` still writes both DM(0x3309) and
DM(0x2F22); GEN_setup2 quality control and its request flags are not pinned.


Concrete results from `artifacts/retrain-20261013-fixed`:

- Caller DATA starts at sample 179680 (22.460 s), and the last CSV record
  at 776640 (97.080 s) is still DATA: 74.620 seconds continuously.
- Answerer DATA starts at 166400 (20.800 s), and its final CSV record at
  760960 (95.120 s) is still DATA: 74.320 seconds continuously.
- Neither endpoint logs a DATA exit or a retrain. Both retain DCD/CTS/DSR.
  IPCP and LCP go down only after the harness's requested shutdown.
- CHAP and IPCP complete; all 65 pings receive replies. Both PPP summaries
  report zero FCS errors and zero data-link resets.
- Caller DM(0x0EF7) is 45–58 across the one-second observations, request
  DM(0x1DCB) stays zero, and DM(0x1FA4) is 64. Firmware negotiated a new,
  lower fallback threshold; the test did not retain or increase 320.
- Answerer TX is 41 bits/datagram (`speedTx=0x2034`), or 54,666 bit/s;
  upstream is 13 bits/datagram at 2400 Hz (`speed=0x11F3`), or 31,200 bit/s.
- At 90 s the caller reports zero substituted/dropped RX samples and zero
  TX underruns. There were four clock holds totaling 8 ms and five ticks
  over 18 ms; this is not a claim of a perfectly jitter-free run.

`artifacts/retrain-20261013-evidence.json` contains extracted endpoint
summaries. Use its **first contiguous DATA duration**, because the baseline
later re-enters DATA and its last DATA row cannot establish an uninterrupted
link. The new output-boundary regression checks the PCMU alphabet through
companding, signed zero, full scale, page/law/backend gating, context restore,
and preservation of the channel-law configuration. All 32 V.90 Python tests,
