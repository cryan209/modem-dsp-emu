## V.90 upstream defect fixed

Follow-up isolated replay found a carrier/equalizer coordinate error in
v90modem's T/3 receiver: decision errors after carrier derotation were used
against unrotated input. Correct NLMS returns the error to input coordinates
using the original per-symbol phase. CMA recovery needs the same rotation.
Committed in `/Users/scottcryan/v90modem` as `e72c35e0`; see that repository's
`docs/mt9234_v90_gradient.md` for derivation, fixture and validation.

Two corrected physical calls held V90 for requested 60-second DTE holds:
40000/26400 and 46666/26400 down/up, LAPM/V42bis, no retrains or rate changes.
Both received all 20 exact numbered downstream lines. The second delivered
1920 upstream bytes byte-exact; ATI11 reported one TX frame error and zero
RX frame errors. First had zero TX/RX errors. Both hung up cleanly.
DTE evidence: `emu-gradient-1/` and `emu-gradient-2/` in the run directory.
Full server evidence is under `/root/mt9234-debug-20261028/` on CT117.
Temporary corrected listeners were stopped; no permanent service or other
running test was replaced. The canonical Mac emulator source and build have
the fix. Automatic approval review rejected the direct origin/main push;
the commit remains local pending explicit user authorization to push.

Fast suite: 629 passed, one unrelated plain V34 A-law rate-expectation failure
reproduced with our correction removed. New finite-difference and recorded-call
regressions pass; the recorded-call regression fails before the correction.

pseudorandom bytes in each direction, sequentially, over V90 46666 down /
26400 up, LAPM/V42bis. Both ends checked every byte and SHA-256; data is
incompressible for practical throughput measurement. No dial/training time
is included in the transfer timings.
