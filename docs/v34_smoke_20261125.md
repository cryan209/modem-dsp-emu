# Local V.34/LAPM/PPP smoke, 25 November 2026

The current local Analog/PRI loopback completed V.34 data mode, established
LAPM once on each end, authenticated CHAP, brought up IPCP and answered
**20/20 pings**. Both final PPP summaries report **zero FCS errors and zero
data-link resets**. This is a fresh emulated-endpoint result, not a physical
line/card run or a sustained payload qualification.

## Command

From the repository root, with the project environment built and the matching
Analog109/PRI117 kernel/task/overlay extractions available:

```sh
.venv/bin/python -u tools/eicon_loopback.py \
  --python .venv/bin/python --seconds 60 \
  --caller-firmware-set analog109 --answerer-firmware-set pri117 \
  --modulation v34,0,19200,19200,19200,19200 \
  --caller-kernel-dispatch --ppp --ppp-ping peer --ppp-ping-count 20 \
  --trace-retrain --sip-port 25070 --rtp-port 24010 \
  --capture-dir artifacts/test-results/v34-smoke
```

The harness bound only localhost: answerer SIP/RTP 25070/24010, caller
25072/24012. It used the normal 2-second setup gap, caller kernel dispatch,
answerer direct backend, and default current media buffering. No physical
modem, registrar account or production service was used. Both child endpoint
processes stopped at the end of the bounded run.

## Observed criteria

| Check | Caller | Answerer |
| --- | --- | --- |
| V.34 data mode | `TrnProgress 0x00d0` | `TrnProgress 0x00d0` |
| LAPM establishment | One connection, UA received | One connection, SABME received |
| CHAP authentication | `ppp` authenticated | `ppp` authenticated |
| IPCP | `100.64.0.2` → `100.64.0.1` | `100.64.0.1` → `100.64.0.2` |
| Final PPP FCS errors | 0 | 0 |
| Final data-link resets | 0 | 0 |
| Last reported RX substituted/dropped | 0 / 0 | 0 / 0 |
| Last reported TX underruns | **42** | **39** |

Caller ping sequences were exactly 1 through 20, with exactly one reply for
each. Reported RTT was **258–340 ms**, median **272.5 ms**. There was no
`EICON_V42_RETRANSMIT_AFTER` override.

The underruns are not hidden: this test ran alongside the native regression
gate, and the endpoints reported roughly 0.82–0.85 times real-time media
progress late in the call. Successful PPP here does **not** establish an
underrun-free wire clock or acceptable physical-peer timing. Both emulated
ends can tolerate the same slowdown. The logs show the limitation explicitly.

- `artifacts/test-results/v34-smoke.log`: parent command/run summary.

The general loopback runner still exits successfully after a timed run even
when no PPP verdict has been established. Its exit status alone was **not**
used as the smoke verdict; endpoint logs were inspected and the criteria
above checked separately.

Follow-up: the [executable qualification command](v34_qualification.md) now
checks exact independent bytes in both directions and repeated calls against
one persistent answerer, including SIP BYE/PPP teardown. Its bounded
stop-and-wait exchanges are still not full-bandwidth TCP or long-soak proof;
this earlier ping smoke does not substitute for those tests. See the original
[T401 diagnosis](v34_data_mode_t401_20261023.md) for why negotiation previously
failed even after the modem reached data mode.
