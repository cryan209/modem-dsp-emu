# V.34 high-rate data after the ADC overflow correction — 14 October 2026

The ADSP emulator incorrectly computed signed overflow for add-with-carry.
Correcting that instruction permits the mixed Analog/PRI firmware pair to
carry PPP at 21,600, 26,400 and unrestricted-negotiated 31,200 bit/s with
its normal quality controls enabled. The unrestricted run also transfers a
complete 64 KiB file over one TCP connection with a matching SHA-256.

## Arithmetic defect and regression

In all five ALU add-with-carry helpers, `2100ops.inc` added the carry input to
the Y operand before computing overflow. That changes Y's sign when it crosses
`0x7fff` or `0xffff`, so AV can become set for a valid signed sum:

| X | Y | Carry in | Correct result | Correct AV |
| --- | --- | --- | --- | --- |
| `0x7fff` | `0xffff` | 1 | `0x7fff` | 0 |
| `0x8000` | `0x7fff` | 1 | `0x0000` | 0 |

With AR saturation enabled, the first case incorrectly became `0x8000`.
The carry input now contributes to the result while overflow uses the original
operands. Carry-out still uses the full unsigned sum. The ADSP-218x Hardware
Reference, [Computational Units](3110043388x_hardware/8xcompu.pdf), defines
AV from the original two's-complement operands and AC from unsigned carry-out.

The new C-core regression failed against the old implementation. The fixed
core passes 272 boundary cases across AR, AF, flags-only and both constant
operand forms, checking AZ/AN/AV/AC, real overflow, AR saturation and the
unchanged destination for flags-only operations.

```sh
make -C tools/adsp2181emu test libadsp2181.dylib
```

## Closed-loop evidence

The pre-fix normal-option 21600 capture
`artifacts/v34-20261014-21600-fixed` retrains twice and never opens IPCP.
The answerer initiates the first excursion. A bounded write watch resolves
its marker to PM `0x2d66`, reached through the event dispatcher at `0x2490`.
Receive residual writers are PM `0x3204/0x3206`; the error average is published
at `0x325e`. These establish the failing receive path, but do not identify a
particular execution of ADC as the first wrong operation.

The core arithmetic change is the only functional change between that baseline
and the successful normal-option runs below. No database override, retrain
suppression, rate-quality pin, PLL patch or forced training state is used in
these V.34 passes.

| Capture | Rate in both directions | Duration | Peer pings | Retrains | PPP FCS errors / resets |
| --- | ---: | ---: | ---: | ---: | --- |
| `v34-20261014-adc-fixed` | 21600 | 40 s | 10/10 | 0 | 0 / 0 |
| `v34-20261014-adc-26400` | 26400 | 60 s | 30/30 | 0 | 0 / 0 |
| `v34-20261014-adc-unrestricted` | 31200 (unrestricted negotiation) | 100 s | 65/65 | 0 | 0 / 0 |

At 21600 both ends publish nine bits per 2400-Hz datagram. The answerer's
SNRatio settles at `0x003f` with Signalquality zero, instead of the pre-fix
falling SNR and Signalquality 7. At 26400 both ends publish eleven bits per
datagram, `speedTx=0x0011`, `DATASTATESpeed=0x1111`.

Reproduce the 26400 result:

```sh
/Users/scottcryan/v90modem/.venv/bin/python tools/eicon_loopback.py \
  --python /Users/scottcryan/v90modem/.venv/bin/python --seconds 60 \
  --caller-firmware-set analog109 --answerer-firmware-set pri117 \
  --modulation v34,0,26400,26400,26400,26400 --caller-kernel-dispatch \
  --ppp --ppp-ping peer --ppp-ping-count 30 --trace-retrain \
  --capture-dir artifacts/v34-26400-repeat
```

These are local closed-loop firmware data results. Physical-line high-rate
interoperability is not established by this change.

## Unrestricted negotiation and TCP payload

Use `--modulation v34,0` to let the firmware select its normal line rate.
The 100-second run negotiates `speedTx=0x0013`, `DATASTATESpeed=0x1113` on
both ends: thirteen bits per 2400-Hz datagram, or 31200 bit/s. Caller DATA
spans captured samples at 17.24–97.04 seconds; answerer DATA spans
15.50–95.12 seconds. Neither endpoint records a retrain.

The source and sink each contain 65536 bytes with SHA-256
`16caabbba728f0436dcb1bebf39764f23aa450550456fce599f20522c3925414`.
The source was generated by SHAKE-256 from the ASCII seed
`modem-dsp-emu V.34 ADC regression 2026-10-14`, so it is reproducible.
The transfer uses one TCP stream via the PPP client and answerer's userspace
NAT, received by `tools/tcp_file_sink.py`. It is not divided into multiple
application transfers. Source and received files are
`/private/tmp/v34-adc-payload.bin` and `/private/tmp/v34-adc-received.bin`.

```sh
/Users/scottcryan/v90modem/.venv/bin/python tools/tcp_file_sink.py \
  /private/tmp/v34-adc-received.bin
# In a second terminal:
/Users/scottcryan/v90modem/.venv/bin/python tools/eicon_loopback.py \
  --python /Users/scottcryan/v90modem/.venv/bin/python --seconds 100 \
  --caller-firmware-set analog109 --answerer-firmware-set pri117 \
  --modulation v34,0 --caller-kernel-dispatch \
  --ppp --ppp-ping peer --ppp-ping-count 65 \
  --ppp-tcp-upload /private/tmp/v34-adc-payload.bin --trace-retrain \
  --capture-dir artifacts/v34-unrestricted-repeat
```

Machine-readable summaries, source hash and payload hashes are retained in
`artifacts/v34-adc-20261014-evidence.json`.

The V.90 regression control (`artifacts/v90-20261014-adc-control`, 65 s)
also passes 30/30 PPP pings with no retrain, FCS errors or link resets.
It retains the existing Analog V90A PLL diagnostic
`EICON_PATCH_PM=0x0e3a:0x0a000f:0x026b` and the existing PRI PCMU fixes.

Validation: C core tests, including the 272 new ADC cases, and 171 Python
tests pass (Analog kernel, mailbox, V90D TX/law, LAPM, NL data bridge,
disassembler, direct modulation and loopback environment). `make all`
rebuilds the CLI and shared library; `git diff --check` passes.
